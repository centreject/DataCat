# 물품 존재 상태와 사진 접수 연결

## 적용 기준

`origin/feature/app-design`의 `판정표.md`를 기준으로 한다.
확인한 커밋은 `e70b731`(2026-10-24), 문서의 정책 수정일은 2026-10-23이다.

이전의 물품 개수 비교 기준은 사용하지 않는다. 모델이 물품을 한 개 이상 감지했는지만 사용한다.
사진마다 개수가 달라져도 이미 물품이 있는 상태라면 새 도착으로 판단하지 않는다.

| 입력 | 저장·응답 | 푸시 |
|---|---|---|
| A3, 물품 상태 없음 | 물품 방문 생성, 상태 저장, HTTP 201 | 새 알림 |
| A3, 물품 상태 있음 | 기존 packageEventId 반환, lastSeenAt 갱신, missCount=0, HTTP 200 | 없음 |
| A5 한 번 | missCount=1, 물품 상태 유지 | 없음 |
| A5 두 번 | 물품 상태 행만 삭제, 방문 이력 유지 | 없음 |
| 물품이 다시 보임 | 기존 상태가 있으면 미감지 횟수를 0으로 되돌림 | 기존 물품은 재알림 없음 |
| A0 또는 물품이 안 보이는 A1/A2/A4 | 물품 상태를 비우거나 미감지 횟수를 늘리지 않음 | 사진 판정표의 기존 규칙 |
| 물품이 포함된 응대 세션 종료·음성 완료 | 이 세션을 packageEventId로 기록 | 종료·음성 결과의 기존 갱신 알림 |

물품 상태가 계속 있는 동안 firstSeenAt은 유지한다. 새로운 응대 세션을 이미 알렸다면
packageEventId를 해당 세션으로 갱신한다. 상태를 비웠다가 다시 물품을 보면 새 firstSeenAt을 기록한다.

## 방문 병합과의 관계

- 음성 접수가 진행 중인 방문의 30초 내 사진은 기존 방문에 모은다.
- 응대 중 물품만 보이는 사진이 들어와도 방문을 임의로 COMPLETED로 바꾸지 않는다.
- 세션 사진에서 물품을 한 번이라도 봤으면 packageSeen=true를 유지한다.
- 물품만 남은 완료 기록 뒤에 사람이 오거나 버튼으로 새 응대를 시작하면 새 방문을 만든다.
  이전 물품 방문 이력과 사진을 새 응대로 덮어쓰지 않는다.
- 그 외 방문의 기존 30초 병합·사진 분류 우선순위는 유지한다.
- A3 물품 상태 재사용은 30초가 지나도 적용한다. 시간 경과만으로 재알림하지 않는다.
- A5는 이번 사진의 실제 판정으로 미감지 횟수를 처리한다.
  Event의 누적 분류는 기존 병합 규칙 때문에 A3로 남을 수 있으며, 물품 상태와는 별개다.

## 클래스 역할

| 클래스 | 역할 |
|---|---|
| DeviceEventService | 사진 파일 검사·저장, Vision 호출, 저장 서비스 호출, 커밋 후 사진 정리·푸시 요청 |
| DeviceSessionImageService | 사진 접수의 방문 병합·저장과 물품 상태 갱신을 하나의 트랜잭션으로 처리 |
| PackageReceptionService | 기기별 물품 존재 상태와 미감지 횟수 관리 |
| DevicePackageState | packagePresent, missCount, 연결 방문 번호, 최초·마지막 확인 시각 저장 |
| Event | 세션 중 물품을 봤는지 packageSeen으로 기록 |
| DeviceSessionEndService | 종료 판정에 물품 개수 대신 packageSeen 전달 |

Vision HTTP 호출 중에는 DB 트랜잭션을 열지 않는다.
방문과 물품 상태 저장이 모두 커밋된 뒤에 푸시를 요청한다.
실패하면 두 DB 변경을 함께 롤백하고 새 사진을 정리한다.
같은 물품 재감지 때 사용하지 않는 새 사진은 삭제하고 기존 방문의 사진은 유지한다.
새 방문을 만들었을 때 이전 방문의 사진을 삭제하지 않는다.

## 기존 DB 호환

- Event에 nullable packageSeen 컬럼을 추가한다. 값이 없는 과거 기록은 maxPackageCount > 0으로 읽는다.
- DevicePackageState에 nullable packagePresent, missCount 컬럼을 추가한다.
  과거 행의 null은 기존 package_count > 0과 미감지 0회로 읽는다.
- 기존 MySQL의 NOT NULL package_count 컬럼은 호환용으로 유지한다.
  새 행의 호환 값은 1이며 새 판정에서 개수를 비교하지 않는다.
- 기존 Event의 maxPackageCount와 정수 종료 판정 메서드는 호환을 위해 남기지만,
  현재 종료 서비스의 업무 판정은 boolean packageSeen을 사용한다.
- 개발용 ddl-auto=update에서 컬럼을 추가한다. 기존 테이블·방문·사진을 삭제할 필요가 없다.
  운영용 DB 마이그레이션 구성은 별도 작업이다.

## 자동 검증 범위

H2 기반 서비스 시험과 실제 Controller·파일 저장을 연결한 MockMvc 시험을 포함한다.
Vision 응답과 FCM 발송은 가짜 객체를 사용한다.

- 30초 병합 범위 밖에서도 같은 물품을 재알림하지 않음
- 물품 개수 증가·감소를 새 도착으로 보지 않음
- A5 한 번은 유지, 두 번은 상태만 삭제, 물품 재감지는 새 도착
- 물품이 다시 보이면 미감지 횟수 0
- 가려진 사진·사람 응대·모델 장애를 물품 부재로 세지 않음
- 물품 방문 뒤 새 사람·버튼 응대의 방문 번호 분리
- 응대 중 물품 사진을 세션에 누적, 종료 후 물품 상태 기록
- 음성 완료 후 물품 사진이 들어와도 음성 결과 보존
- 모델 호출은 DB 트랜잭션 밖, 푸시는 커밋 뒤 호출
- 물품 저장·삭제 실패 시 방문·물품 상태 롤백 및 사진 정리
- 과거 컬럼이 null인 행의 호환 읽기

물품 정책 연결 시점에 자동 테스트 138개, 동시 실패 처리 추가 후 최종 145개가 통과했다(실패·오류·건너뜀 0).
실제 MySQL에서도 15~18번 방문으로 30초 이후 물품 재사용·1회 미감지 유지·2회 해제·재도착 새 방문을 확인했다.
새 nullable 컬럼 추가와 기존 기록 보존을 확인했다. 실제 Pi·휴대폰 알림은 별도 통합 확인 대상이다.
전체 검증 기록은 [8주차 검증 기록](week8-verification.md)을 따른다.

## 남은 구현·협의 사항

- A0와 음성 503의 종료는 추가 연결했다. `model-failure-handling.md`의 세부 값은 구현 제안으로 구분한다.
- 종료 요청의 선택 사진 multipart 지원은 아직 추가하지 않았다. 현재 JSON 종료 요청은 유지한다.
- 이미지의 촬영 ID·재전송 ID는 도입 전이다. 현재는 검증된 A5 요청 두 건을 미감지 두 건으로 센다.
  동일 사진 재전송과 새 촬영을 확실하게 구분할 식별자 계약은 TBD다.
- 완료된 음성 방문에 다시 벨을 누르는 유예 동작과 별개 새 방문의 경계는 추가 협의 대상이다.
  이번 변경에서는 물품만 남은 완료 기록 뒤의 새 응대를 분리한다.
- 한 Spring 프로세스의 synchronized 처리는 유지한다. 여러 인스턴스의 동시성은 별도 작업이다.
