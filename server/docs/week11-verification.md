# 11주차 구현 검증 기록

검증일 2026-11-08. 기준은 PR #11의 c102bb0345fcfe7c66370c4a5f132575966ff998이며, 이 문서는 패치 준비 환경에서 수행한 결과다. 사용자의 Windows 적용·커밋·푸시나 실장비 완료를 의미하지 않는다.

| 항목 | 결과 | 범위 |
| --- | --- | --- |
| Spring 자동 테스트 | 155개, 실패·오류·건너뜀 0 | 기존 147개와 신규 8개. H2·모의 모델 응답 사용 |
| Pi 코드 자동 테스트 | 40개 통과 | 기존 33개와 신규 7개. 센서·음원·녹음·HTTP는 모의 객체 |
| Compose 설정 | 기본 모의 구성·실제 모델 보조 구성 모두 config --quiet 통과 | Compose v5.5.1, 컨테이너 실행 시험과 구분 |
| HTTP 재현 도구 | PASS | 실제 Spring HTTP + H2 + 저장소의 mock 모델 서비스. 자동 만료를 2초, 점검을 200ms로 단축 |

서버 시험은 Java 21.0.13에서 수행하였다. 검증 환경의 Mockito 자동 연결 제약 때문에 저장소 밖의 임시 Gradle init 설정으로 테스트 JVM 시작 시 Mockito 에이전트를 연결했다. 사용자 PC용 build.gradle이나 gradlew는 수정하지 않았다.

신규 서버 시험은 DEVICE_CANCELLED의 확인 필요 표시와 재요청 보호, 예전 데이터의 만료 경계, 최신 사진·음성 수신으로 기한 갱신, 완료 결과 보존, 커밋 뒤 1회 알림 요청, 만료 후 늦은 음성 409, 최신 물품 상태 보존, 모델 처리와 타이머의 동시 실행 보호를 확인한다. 별도 자동 스케줄러 시험에서는 Pi의 종료 요청 없이 방문이 완료되는지 확인하였다.

HTTP 재현에서는 check_session_safety.py가 정상 배송 방문·일반 종료 방문·장치 중단 방문·후속 요청 없는 방문을 생성했다. 장치 중단은 200 END_SESSION과 단말 확인 필요로 저장됐고, 대기 방문은 자동 만료됐다. 만료 후 음성은 409였으며 기존 정상 배송 기록과 사진은 유지됐다. 단축한 만료 설정에서 점검까지 관측한 대기는 약 3초이며, 기본 120초 설정을 실장비에서 측정한 값이 아니다.

미실행: 사용자의 Windows 자동 테스트·Docker 이미지 재빌드/컨테이너 실행, MySQL에서 새 열 추가 후 재현, 기본 120초 실측, 실제 GPU 추론, 실제 Pi 장치 송수신·음원 청취, 새 구성의 휴대폰 푸시 수신. 해당 항목은 사용자의 후속 시험으로 남긴다.
