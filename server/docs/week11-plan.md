# DataCat 11주차 서버 개발과 장치 오류 시험

## 이번 주 목표

10주차까지의 실제 모델 Docker 설정과 통합 시험 절차에 장치 오류 대응을 보완한다. 담당은 조인태(Spring)이며 Pi 코드는 수연님이 검토·반영할 수정 제안으로 제공한다. 실제 모델/GPU/Pi 통합 시험과 안내가 들리는지 확인하는 시험은 장비와 팀 일정이 준비되면 진행한다.

1. 서버의 대기 방문 자동 만료와 단말 중단 요청 지원.
2. Pi 안내 재생 실패 시 녹음 차단 및 장치 오류 종료 통보.
3. 기존 정상 응대·재전송·늦은 종료를 회귀 시험.
4. 시험할 Spring 서버 한 대의 IP·외부 포트를 정하고 Pi·앱에 같은 주소 사용.
5. PR #11의 기존 변경과 이번 변경을 팀에서 검토한 뒤 반영.

## 구현한 동작과 역할

### 서버

- 새 종료 사유 DEVICE_CANCELLED를 지원한다. 기존 명세의 예약 값을 사용한 11주차 구현 제안이다. 이탈·무발화와 구분해 단말 확인 필요/needsReview=true로 남긴다. 사진에서 물품을 본 여부는 보존한다.
- WAITING_AUDIO의 마지막 사진·음성 수신 후 기본 120초 동안 후속 요청이 없으면 자동 종료한다. 5초마다 최대 100건을 점검하므로 정확히 120초에 실행되는 보장은 없다. 현재 처리 중인 모델 요청이나 밀린 점검이 있으면 더 늦어진다.
- 사진 접수와 음성 재시도는 서버 수신 시각으로 기한을 다시 계산한다. Pi 시각을 사용하지 않는다. 기존 DB 기록은 마지막 사진 수신 시각, 그것도 없으면 발생 시각을 사용한다.
- 정상 분석 중인 방문은 기존 접수와 같은 단일 프로세스 잠금으로 보호한다. 이미 완료된 방문은 덮어쓰지 않고, 만료 후 음성은 409로 거절한다. 새 방문으로 접수한다.
- 저장 커밋 뒤 같은 방문의 알림 갱신을 한 번 요청한다. FCM을 켜지 않으면 실제 푸시는 보내지 않는다. 만료가 물품을 재관측한 것은 아니므로 현재 잔류 물품 상태는 수정하지 않는다.
- last_session_activity_at 열 하나를 추가한다. 현재 개발 설정 ddl-auto=update를 사용한다. 서버를 다시 켜도 이전의 대기 방문을 정리하며, 시작할 때 이미 오래된 대기 기록도 첫 점검부터 대상이다.

### Pi 수정 제안

- 인사 음원 파일이 없거나 aplay가 실패·시간 초과하면 마이크를 열지 않는다. 정식 안내를 삐 소리로 대체하고 계속 녹음하던 경로를 제거한다.
- 재생 실패나 마이크 OSError는 DEVICE_CANCELLED로 종료를 요청한다. 종료 통보까지 실패하면 서버 자동 만료가 대기 기록을 정리한다.
- 마이크 무발화 5초와 VISITOR_LEFT 처리는 유지한다. 안내 재생 성공 이후에만 녹음을 시작한다.
- 물리적 스피커 손상·음소거가 있어도 aplay가 성공할 수 있다. 이번 수정은 재생 명령의 오류를 다루며 실제 소리가 들렸다는 증명은 아니다. 사람이 안내 청취를 확인한다.
- 서버가 기록을 종료해도 멈춘 Pi의 마이크를 원격으로 닫거나 Pi 전원을 재시작하지는 않는다. 실제 장치 복구는 별도다.

## 설정과 주소

| 항목 | 기본값 | 의미 |
| --- | --- | --- |
| SESSION_IDLE_TIMEOUT_MS | 120000 | 서버 방문의 비활동 만료 기준. 실측 전 시작값 |
| SESSION_EXPIRY_CHECK_MS | 5000 | 점검 간격 |
| SESSION_EXPIRY_ENABLED | true | 자동 만료 활성화 |
| MODEL_AUDIO_READ_TIMEOUT_MS | 5000 | Spring → 모델의 응답 읽기 대기 |
| Pi HTTP 대기 | 10초 | Pi → Spring 요청 대기 |
| Pi 무발화 대기 | 5초 | 마이크를 연 뒤 발화를 기다리는 시간 |

Docker에서는 위 SESSION_* 값을 DATACAT_TEST_SESSION_* 환경변수로 전달한다. 서버 외부 포트는 기본 18080이며 컨테이너 내부 Spring은 8080이다. 수연님 PC에서 직접 실행하는 Spring이 8080이면 그 서버를 사용할 때 Pi·앱에는 http://수연님_PC_IP:8080을 넣는다. 네 Docker 서버를 사용하면 http://네_PC_IP:18080이다. 원격에서는 도달 가능한 주소가 추가로 필요하다.

120초·장치 오류 표시·DEVICE_CANCELLED 지원은 이번 제안값이다. 명세·Pi 담당 검토와 실장비 시험 후 확정한다. 여러 Spring 인스턴스의 분산 잠금·원격 마이크 차단·주기적 heartbeat API는 이번 범위에 포함하지 않았다.

## 적용 순서

기준 커밋은 PR #11의 c102bb0345fcfe7c66370c4a5f132575966ff998이다. GitHub 상태는 별도 갱신될 수 있으므로 적용 시 깨끗한 작업 폴더와 git apply --check를 확인한다.

1. 서버 패치 적용 → Java 21의 gradlew.bat test 통과.
2. 사용 중인 Docker Compose 조합 그대로 api를 다시 빌드·실행. 기본 모의 환경이라면 datacat-stack에서 docker compose -f docker-compose.server.yml up -d --build --wait --wait-timeout 300. 실제 모델·FCM 환경은 기존 -p와 모든 -f 옵션을 동일하게 유지한다.
3. 서버가 DEVICE_CANCELLED를 받아 주는 것을 확인한 뒤 Pi 담당이 별도 Pi 패치를 검토·적용한다. 기존 서버는 이 사유를 400으로 거절하므로 순서를 지킨다.
4. 실제 모델/Pi/앱 시험 결과를 기록한 뒤 완료 판정을 한다. 코드 시험 통과와 실장비 완료를 혼용하지 않는다.

## Pi 없이 할 수 있는 서버 시험

기존 사진 접수 도구나 curl.exe로 사람 사진(모의 모델은 person.jpg 파일명)과 metadata를 POST /api/v1/device/events에 보내 eventId를 받는다. 같은 기기의 사진은 30초 안에 병합될 수 있으므로 사례별로 다른 deviceId를 쓴다. 테스트 DB에서 진행한다.

| 사례 | 동작 | 통과 기준 |
| --- | --- | --- |
| Pi 중단 대체 | 사진 접수 후 아무 후속 요청도 보내지 않고 2분 이상 대기 | GET /api/v1/events/{id}에서 COMPLETED, 단말 확인 필요, needsReview=true, 만료 원인 |
| 장치 오류 | 대기 방문에 /end JSON reason=DEVICE_CANCELLED, 현재 endedAt 전송 | 200 END_SESSION, 장치 중단 원인. 재전송해도 종료 시각과 결과 유지 |
| 정상 음성 | 사진 후 WAV를 보내기 | 정상 분류·요약 저장. 2분 뒤에도 기존 결과 유지 |
| 늦은 음성 | 만료된 방문에 WAV 전송 | 409. 새 방문으로 전송하면 정상 접수 |
| 정상 무발화 | /end reason=TIMEOUT 전송 | 기존 무발화 종료이며 장치 오류로 표시되지 않음 |
| 재시작 | 대기 방문 생성 후 서버만 재시작 | 대기 기록이 남아 있고 기한 경과 후 자동 만료. 볼륨 삭제 금지 |

기본 모의 시험은 저장·상태 전환 시험이다. 실제 사람·물품 인식 정확도나 스피커 청취 시험이 아니다. 기존 smoke_server.py의 완료된 사진·음성·종료 기록 유지 시험도 그대로 사용할 수 있다.

## 장비가 준비되면 함께 할 시험

| 담당 | 시험 | 기록 |
| --- | --- | --- |
| 수연님·조인태 | 인사 음원 누락 또는 잘못된 출력 장치로 재생 실패 | 마이크 개방 로그가 없어야 함. DEVICE_CANCELLED의 eventId와 저장 결과 |
| 수연님·조인태 | 사진 접수 후 Pi 프로세스 종료 또는 네트워크 분리 | 서버는 계속 서비스, 해당 방문은 기한 후 자동 만료 |
| 세 담당 | 실제 발화 → 모델 분석 → 완료 안내 → 앱 확인 | 실제 처리 시간·분류·음원 청취·동일 eventId·푸시 수신 |

실제 안내가 들리지 않는데 aplay는 성공하는 경우는 별도로 기록한다. 타이머는 단말 오류 원인을 확정하지 않는다. 마이크와 출력 장치는 시험 전에 각각 확인한다.
