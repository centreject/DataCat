# 이미지·음성 분석 동시 실패 처리

## 판정표에서 확인된 방향

`origin/feature/app-design`의 판정표 A0는 이미지 분석에 실패해도 음성 접수를 시작하고,
음성 분석도 실패하면 B2와 같이 `기타·판단 불가`로 끝내도록 정의한다.
사진 단계의 `이미지 판단 실패`와 `needsReview=true`를 보존한다.

분석 결과가 없는 상황에서 transcript, purpose, summary를 임의로 만들지 않는다.
음성 파일을 정상 처리했다는 성공 응답이나 완료 프리셋 2번을 반환하지 않는다.

## 현재 연결한 동작

| 조건 | Event 처리 | HTTP 응답 |
|---|---|---|
| 정상 사진 A1/A2 뒤 음성 모델 503 | WAITING_AUDIO 유지. 같은 방문에 재시도 가능 | 기존 503 오류 JSON |
| 아직 음성 성공이 없는 A0 방문에서 음성 모델·응답 사용 불가 503 | 기타·판단 불가로 종료. DB 저장 완료 뒤 푸시 갱신 요청 | 기존 503 오류 JSON |
| A0 방문이지만 음성 파일 형식 오류 400 | WAITING_AUDIO 유지 | 400 오류 JSON |
| A0 뒤 정상 음성 분석 또는 NO_SPEECH 응답 | 기존 표 C 적용. 사진 실패 표시 보존 | 기존 200, PLAY_PRESET 2 |
| 이전 음성 분석이 이미 성공했고 추가 분석에서 503 | 기존 성공 결과와 종료 시각 보존 | 503 오류 JSON |
| 오류 종료된 방문에 뒤늦은 음성 | 다시 열지 않음 | 409 EVENT_STATE_CONFLICT |
| 오류 종료된 방문에 뒤늦은 /end | 기존 실패 분류와 종료 시각 보존 | 200 END_SESSION |
| 오류 종료 저장 중 DB 작업 실패 | 종료 변경 롤백. 푸시 요청 안 함 | 500 오류 JSON |

503 응답 본문은 기존 `code`, `message` 형식을 유지한다.
503 뒤에도 Event를 조회하면 최종 상태를 확인할 수 있다.
COMPLETED는 접수 처리가 끝났다는 뜻이며 모델 분석 성공을 보장하는 값은 아니다.

## 세부 값 — 구현 제안, 팀 확인 대상

다음 조합은 A0의 종료 방향을 구체적으로 연결한 제안이다.
확정된 별도 오류 판정표가 생기면 그 기준으로 맞춘다.

| 필드 | 현재 제안 구현 값 | 이유 |
|---|---|---|
| eventType | VISITOR_TIMEOUT | 판정표 B2의 기존 코드 사용. 새 eventType을 추가하지 않음 |
| mainCategory | 기타·판단 불가 | A0에 명시된 최종 분류 방향 |
| responsePolicy | 장애 안내 | 기존 허용 값 중 오류 안내에 해당하는 값 |
| processingStatus | 이미지 판단 실패 | A0의 사진 실패 표시 유지 |
| reason | 이미지·음성 분석 실패 | 방문객 이탈·무발화 시간 초과를 실제 발생한 것처럼 기록하지 않음 |
| needsReview | true | A0의 사용자 확인 필요 값 유지 |
| status | COMPLETED | 접수 종료 |
| transcript / purpose / summary / audioHash | 새로 저장하지 않음 | 성공 분석 결과가 없음 |

`VISITOR_TIMEOUT`은 기존 B2 코드의 재사용이다. 실제 오류 원인은 reason으로 구분한다.
오류로 완료된 방문을 재시도로 다시 열지 않는 정책도 이 구현 제안에 포함한다.
서버는 성공 JSON으로 PLAY_PRESET 3을 새로 반환하지 않는다.
Pi가 HTTP 503을 받아 로컬 오류 음원 3번을 실제 재생하는 동작은 Pi 담당자와 통합 확인해야 한다.

## 코드 흐름

1. DeviceEventService가 음성 모델을 호출한다. 모델 호출 중 DB 트랜잭션은 열지 않는다.
2. 음성 처리에서 503 예외가 발생하면 DeviceSessionAudioService의 별도 저장 메서드를 호출한다.
3. 상태가 WAITING_AUDIO이고 사진 판정이 A0인 방문에만 오류 종료를 적용한다.
4. 방문 종료와 필요한 물품 상태 기록을 하나의 트랜잭션으로 저장한다.
5. 커밋이 끝난 뒤 기존 비동기 푸시 경로로 갱신을 요청한다.
6. 원래 503 예외를 유지해 Pi가 분석 실패를 알 수 있도록 한다.

## 검증

- A0와 음성 503: 종료·분류·원문 비저장·커밋 후 푸시, HTTP 503 유지
- 정상 사진의 음성 503 후 복구 재시도: 기존 동작 유지
- A0 뒤 잘못된 음성 400: 대기 상태 유지
- A0 뒤 NO_SPEECH 정상 결과: 표 C 적용
- 성공한 음성 결과의 재분석 실패: 기존 결과 보존
- 오류 종료 뒤 음성 재요청과 늦은 /end: 상태 보존, 중복 푸시 없음
- 오류 종료 저장 중 DB 작업 실패: 롤백, 푸시 없음

2026-10-25 Java 21 검증 환경에서 전체 자동 테스트 145개가 통과했다.
실제 MySQL에서도 19번 방문으로 사진 실패 후 음성 503, COMPLETED 오류 종료와 분석 값 null 보존을 확인했다.
20번 방문에서는 이미지·음성 분석 실패 결과의 휴대폰 알림 수신도 확인했다.
Pi가 HTTP 503을 받아 로컬 오류 음원을 재생하는 동작은 별도 통합 확인 대상이다.
전체 검증 기록은 [8주차 검증 기록](week8-verification.md)을 따른다.
